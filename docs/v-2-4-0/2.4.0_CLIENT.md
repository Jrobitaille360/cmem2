# Guide migration client — v2.3.1 → v2.4.0

## Résumé des changements

| Zone | Type | Impact client |
| - | - | - |
| Abonnements | Nouveaux champs | `is_trial`, `trial_end` dans les réponses `/subscription/status` et `/subscription/verify` |
| Abonnements | Nouveau endpoint | `POST /subscription/checkout` — génère une session Stripe Checkout |
| Abonnements | Nouveau endpoint | `POST /stripe/webhook` — réservé serveur Stripe, aucune action client |
| Auth OTP | Comportement | `POST /auth/send-code` crée silencieusement le compte si l'email est inconnu |
| Abonnements Google Play | Interne | Migration vers API subscriptionsv2 (transparent pour le client) |

---

## Nouveaux champs dans les réponses d'abonnement

`GET /subscription/status` et `POST /subscription/verify` retournent désormais deux champs supplémentaires :

```json
{
  "is_trial": false,
  "trial_end": null
}
```

| Champ | Type | Description |
| - | - | - |
| `is_trial` | `boolean` | `true` si l'abonnement en cours est un essai gratuit |
| `trial_end` | `string\|null` | Date/heure de fin d'essai (`Y-m-d H:i:s`) ou `null` |

---

## Nouveau endpoint — POST /subscription/checkout

Lance une session Stripe Checkout pour souscrire à un plan.

**Requiert :** JWT valide (`Authorization: Bearer <token>`)

```http
POST /subscription/checkout
Content-Type: application/json

{
  "app_id": "puzzle",
  "plan": "monthly"
}
```

**Réponse 200 :**

```json
{
  "success": true,
  "data": {
    "checkout_url": "https://checkout.stripe.com/...",
    "session_id": "cs_test_..."
  }
}
```

| Code | Cas |
| - | - |
| 200 | Session créée — rediriger l'utilisateur vers `checkout_url` |
| 401 | JWT absent ou invalide |
| 422 | `app_id` ou `plan` manquant/invalide (`monthly` ou `yearly` acceptés) |

---

## Changement de comportement — POST /auth/send-code (Option A)

Si l'email fourni n'existe pas en base, le compte est désormais créé silencieusement avant l'envoi du code OTP. Le client ne reçoit aucune indication différente — la réponse est identique qu'il s'agisse d'un nouvel utilisateur ou d'un utilisateur existant.

Le compte créé automatiquement a `email_verified=1` et aucun mot de passe défini (connexion par OTP uniquement, jusqu'à ce que l'utilisateur en définisse un).

---

## Aucun changement cassant

Tous les endpoints existants conservent leur comportement et leur structure de réponse.
