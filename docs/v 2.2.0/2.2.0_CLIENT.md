# Migration client — v2.1.x → v2.2.0

Ce document liste les changements que les applications clientes doivent prendre en compte
avant de consommer l'API en version 2.2.0.

---

## Changements cassants

### Normalisation des réponses — fichiers

#### Endpoints affectés

| Endpoint | Avant | Après |
| :--- | :--- | :--- |
| `POST /files` | `{ data: { file_id, name, … } }` | `{ file: { id, name, … } }` |
| `GET /files/{id}/info` | `{ data: { file_id, … } }` | `{ file: { id, … } }` |
| `GET /files/user/{id}` | tableau avec `file_id` | tableau avec `id` |

**Action requise** : remplacer toute lecture de `data.file_id` par `file.id` (et `data` par `file`
pour les endpoints info).

---

### Normalisation des réponses — utilisateurs

#### Endpoints affectés

| Endpoint | Avant | Après |
| :--- | :--- | :--- |
| `GET /users/me` | `{ data: { … } }` | `{ user: { … } }` |
| `GET /users/{id}` | `{ data: { … } }` | `{ user: { … } }` |
| `DELETE /users/me` | message texte | `{ deleted: true }` |
| `DELETE /users/{id}` | message texte | `{ deleted: true }` |
| `POST /users/{id}/restore` | message texte | `{ restored: true }` |

**Action requise** : remplacer toute lecture de `data` par `user` pour les endpoints GET.
Adapter la détection de succès des DELETE/restore sur `deleted: true` / `restored: true`.

---

### Normalisation des réponses — groupes

Les endpoints de mutation retournent maintenant `group_id` dans la réponse.

| Endpoint | Champ ajouté |
| :--- | :--- |
| `PUT /groups/{id}` | `group_id` |
| `DELETE /groups/{id}` | `group_id` |
| `POST /groups/{id}/restore` | `group_id` |
| `POST /groups/{id}/leave` | `group_id` |
| `PUT /groups/{id}/members/{user_id}` | `group_id`, `user_id` |

**Action requise** : aucune si le client ne lisait pas de champ `id` dans ces réponses.
Adapter si une confirmation de l'identifiant était attendue.

---

### Normalisation des réponses — tags

| Endpoint | Avant | Après |
| :--- | :--- | :--- |
| `DELETE /tags/{id}` | message texte | `{ tag_id }` |
| `POST /tags/{id}/restore` | message texte | `{ tag_id }` |

**Action requise** : adapter la détection de succès si le client attendait un message texte.

---

### `PUT /tags/{tag_id}/{item_id}` — paramètre `table` renommé, `action` retiré

**Avant (2.1.x)** :

```json
PUT /tags/{tag_id}/{item_id}
Body: { "table": "journaux", "action": "attach" }
```

**Après (2.2.0)** :

```json
PUT /tags/{tag_id}/{item_id}
Body: { "table_associate": "journaux" }
```

Le champ `action` (attach/detach) est déterminé automatiquement côté serveur.
Le champ `table` est maintenant `table_associate`.

**Action requise** : mettre à jour le corps de la requête — renommer `table` → `table_associate`
et retirer le champ `action`.

---

### `GET /stats/users/{id}` — accès restreint aux administrateurs

**Avant (2.1.x)** : un utilisateur pouvait consulter ses propres statistiques via cette route.

**Après (2.2.0)** : la route est réservée aux administrateurs (`role = ADMIN`).
Un appel avec un token utilisateur standard reçoit `403`.

**Action requise** : utiliser `GET /stats/my-stats` pour les statistiques de l'utilisateur connecté
(voir section Nouveautés ci-dessous).

---

### Anti-énumération — `POST /auth/resend-verification` et `POST /users/password-change`

**Avant (2.1.x)** : ces endpoints retournaient des erreurs distinctes selon que l'adresse
email existait ou non dans la base.

**Après (2.2.0)** : réponse toujours `200` avec message générique, quelle que soit l'existence
ou l'état du compte.

```json
200 {
  "message": "Si un compte correspond à cette adresse, un email a été envoyé."
}
```

**Action requise** : ne pas interpréter un `200` comme une confirmation que le compte existe.
Adapter les flux UI en conséquence (toujours afficher le message générique).

---

## Nouveautés (non cassantes)

### `GET /plans/{id}` — détails d'un plan

Retourne le détail d'un plan actif. Route publique, non authentifiée.

```http
GET /plans/{id}
```

```json
200 {
  "plan": {
    "id": 2,
    "name": "Premium",
    "max_groups": 20,
    "max_members_per_group": 50,
    "price": 9.99,
    "active": true
  }
}
```

Retourne `404` si le plan n'existe pas ou est inactif.

---

### `GET /stats/my-stats` — statistiques de l'utilisateur connecté

Remplace l'usage de `GET /stats/users/{id}` pour les utilisateurs non-admin.
Requiert un JWT valide.

```http
GET /stats/my-stats
Authorization: Bearer eyJ...
```

```json
200 {
  "data": { … }
}
```

---

### `GET /plans` — pagination et filtre `active`

L'endpoint supporte maintenant les paramètres de pagination (`page`, `limit`)
et un filtre `active=true|false`.

```http
GET /plans?page=1&limit=10&active=true
```
