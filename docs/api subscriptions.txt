1 — Validation proposition
Android correct : Play ne fournit jamais d'email. L'app reçoit purchase_token + product_id + packageName. Identité = device_token (obtenu au register). JWT ne peut pas être requis.

Win/Web correct : Stripe crée un customer via email. JWT obligatoire.

Note : obfuscatedExternalAccountId dans la réponse Google Play = valeur passée par l'app Flutter au moment de l'achat (setObfuscatedAccountId()). Si anonyme, null. L'API le lit mais ne l'utilise pas (ligne 103-104 de GooglePlayService.php).

2 — Cohérence Playstore / Stripe
Playstore	Stripe
Identifiant fourni	purchase_token + product_id	JWT → user_id + email
Email fourni	Non	Oui (via JWT)
Provider valide côté API	Google Developer API (subscriptionsv2)	Stripe SDK
Anonyme OK	Oui	Non
Les deux flows sont cohérents avec leurs providers. ✓

4 — Corrections à apporter au code
Bogue critique
PlaystoreRouteHandler.php lignes 144–158 : toutes les routes /v2/subscriptions/playstore/* retournent 401 si pas de JWT. Bloque tout utilisateur Android anonyme.

Correction : accepter X-Device-Token (header) comme auth alternative. Si JWT absent → valider device_token via AndroidDevice::findByValidToken(). Passer ['device_token' => ..., 'user_id' => null] au controller.

Bogue secondaire
PlaystoreSubscription.php ligne 26 : upsertSubscription(int $userId, ...) — user_id non nullable. Un anonyme ne peut pas stocker son abonnement.

Correction :

?int $userId
Ajouter device_token nullable comme clé alternative dans la table
findLatestActive et expireStale : chercher par user_id OU device_token
Migration DB requise

ALTER TABLE playstore_subscriptions
  MODIFY user_id INT NULL,
  ADD COLUMN device_token VARCHAR(64) NULL AFTER user_id,
  ADD INDEX idx_device_token (device_token);
Clé unique actuelle doit intégrer device_token :


-- vérifier la contrainte UNIQUE existante avant d'altérer
Mineur
GooglePlayService.php ligne 103–104 : $userId extrait de obfuscatedExternalAccountId est retourné dans le résultat mais jamais utilisé pour lier l'abonnement. Soit l'utiliser pour retrouver le compte, soit retirer le champ du retour pour éviter la confusion.
