# v2.5.0 — Changements visibles client

## Nouveautés

### Portail Stripe — gestion d'abonnement self-service

Nouveau endpoint `POST /subscription/portal` permettant aux utilisateurs connectés
d'ouvrir le Stripe Billing Portal pour gérer (modifier, mettre à niveau, annuler) leur
abonnement directement depuis l'application.

#### Endpoint

```http
POST /subscription/portal
Authorization: Bearer {jwt_token}

{ "app_id": "puzzle" }
```

Réponse `200` : `{ "portal_url": "https://billing.stripe.com/p/session/..." }`

Erreurs :

| Code | Cause |
| - | - |
| 401 | JWT absent ou invalide |
| 404 | Aucun abonnement Stripe trouvé (`errors.error = "NO_SUBSCRIPTION"`) |
| 500 | Erreur Stripe (`errors.error = "STRIPE_ERROR"`) |

### Fichiers — niveau d'accessibilité `grand-public` (sans JWT)

Le champ `accessibility` des fichiers accepte désormais la valeur `grand-public`
en plus de `public` et `private`.

| Valeur | JWT requis | Qui peut accéder |
| - | - | - |
| `grand-public` | Non | N'importe qui, sans authentification |
| `public` | Oui | Tout utilisateur authentifié |
| `private` | Oui | Déposant ou administrateur uniquement |

#### Impact sur les endpoints existants

- **`POST /files`** — le champ `accessibility` accepte `grand-public`
  (réservé aux administrateurs — retourne 403 sinon)
- **`GET /files/{id}`** — accès libre sans JWT si `grand-public`
- **`GET /files/{id}/info`** — accès libre sans JWT si `grand-public`
- **`PATCH /files/{id}/accessibility`** — la valeur `grand-public` est réservée aux administrateurs

## BREAKING CHANGES

Aucun breaking change.

Les fichiers existants conservent leur `accessibility` actuelle. Les nouveaux fichiers
reçoivent `private` par défaut si le champ est omis.
