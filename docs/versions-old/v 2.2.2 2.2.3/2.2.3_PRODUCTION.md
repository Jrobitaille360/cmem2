# Déploiement production — v2.2.3

Checklist à suivre dans l'ordre pour mettre en production la version 2.2.3.

> **v2.2.3 ajoute le support de `RRULE` sur les tâches VTODO (RFC 5545 §3.8.5.4).**
> Une migration SQL est requise.

---

## 1. Migration SQL

### 1a. Phase VTODO RRULE — colonne `recurrence_rule`

```bash
mysql -u <user> -p <database> <<'SQL'
ALTER TABLE calendar_todos
  ADD COLUMN recurrence_rule VARCHAR(255) DEFAULT NULL
  COMMENT 'RRULE RFC 5545 §3.8.5.4'
  AFTER related_to;
SQL
```

Ce script ajoute 1 colonne à la table `calendar_todos` :

| Colonne | Type | Défaut |
| :--- | :--- | :--- |
| `recurrence_rule` | `VARCHAR(255) NULL` | `NULL` |

> La migration utilise `ADD COLUMN` — les tâches existantes reçoivent `NULL` sans interruption de service.

---

## 2. Variables d'environnement

**Aucune variable d'environnement nouvelle requise pour cette version.**

Le `.env` de production issu de la v2.2.2 est compatible sans modification.

---

## 3. Déploiement du code

```bash
git fetch origin
git reset --hard origin/main
composer install --no-dev --optimize-autoloader
```

> `reset --hard` n'affecte pas les fichiers ignorés par git (`.env`, logs, `private/`, etc.).

### Prérequis côté client

La v2.2.3 ne contient **aucun changement cassant**.
Les clients en v2.2.2 continuent de fonctionner sans modification.

Le nouveau champ est documenté dans `docs/v 2.2.2 2.2.3/2.2.3_CLIENT.md`.

---

## 4. Vérifications post-déploiement

### VTODO RRULE

```text
POST /calendars/{id}/todos  (title="Rapport", recurrence_rule="FREQ=WEEKLY;BYDAY=MO")
  → 201, recurrence_rule retourné dans la réponse

GET  /calendars/{id}/todos/{todoId}
  → 200, recurrence_rule présent

GET  /calendars/{id}/ics
  → 200, ICS contient RRULE:FREQ=WEEKLY;BYDAY=MO dans BEGIN:VTODO

POST /calendars/{id}/todos  (recurrence_rule="INVALIDE")
  → 422 (validation RRULE)

POST /calendars/{id}/ics/import  (VTODO contenant RRULE:FREQ=DAILY)
  → 201, recurrence_rule="FREQ=DAILY" enregistré
```

---

## Rollback

La migration est additive (`ADD COLUMN`).
Un retour au tag v2.2.2 ne nécessite pas d'annuler la migration —
la colonne `recurrence_rule` est ignorée par le code v2.2.2.

Si une annulation complète est nécessaire :

```sql
ALTER TABLE calendar_todos
    DROP COLUMN recurrence_rule;
```

Puis retour au code :

```bash
git reset --hard v2.2.2
composer install --no-dev --optimize-autoloader
```
