# v2.17.1 — Changements visibles client

## Nouveau

### Corbeille (soft-delete + restauration) — contacts et projets

Directive cmem_web, task cmemweb #192. Aligne contacts et projets sur le contrat déjà en
place pour événements/todos/journaux du calendrier.

| Méthode | Route |
| - | - |
| `GET` | `/contacts/deleted?page=&limit=` |
| `POST` | `/contacts/{id}/restore` |
| `GET` | `/projets/projects/deleted?page=&limit=` |
| `POST` | `/projets/projects/{id}/restore` |
| `GET` | `/projets/projects/{id}/tasks/deleted?page=&limit=` |
| `POST` | `/projets/tasks/{id}/restore` |

- Fenêtre de restauration de 30 jours (`Contact::RESTORE_RETENTION_DAYS`,
  `Project::RESTORE_RETENTION_DAYS`, `Task::RESTORE_RETENTION_DAYS`) ; `404` sur une fiche
  déjà restaurée, jamais supprimée, ou hors fenêtre.
- Corbeille paginée (défaut 20/page, max 100), triée par date de suppression décroissante.
- `POST .../restore` renvoie l'entité restaurée complète (contrat inchangé).

Référence complète : [docs/contacts/GUIDE.md](../contacts/GUIDE.md#corbeille-et-restauration),
[docs/contacts/API_CONTACTS_ENDPOINTS.json](../contacts/API_CONTACTS_ENDPOINTS.json),
[docs/projets/API_PROJETS_ENDPOINTS.json](../projets/API_PROJETS_ENDPOINTS.json).

## BREAKING CHANGES

- **`DELETE /projets/projects/{id}` n'est plus une suppression physique.** Le projet
  devient invisible (soft-delete, `deleted_at`) au lieu d'être effacé et de cascade-supprimer
  ses tâches et son calendrier caché. Comportement observable identique côté client tant que
  la restauration n'est pas utilisée : le projet et ses tâches disparaissent des listes comme
  avant. Différence concrète : un projet supprimé peut désormais être restauré (avec toutes
  ses tâches intactes) dans les 30 jours, alors qu'avant il était perdu immédiatement et
  définitivement.
