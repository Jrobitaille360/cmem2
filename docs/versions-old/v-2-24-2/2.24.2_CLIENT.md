# v2.24.2 — Changements visibles client

Correctifs du module Assistant et du quota de calendriers. Aucune nouvelle route, aucun
changement de format des réponses.

## BREAKING CHANGES

Aucun.

## Comportement modifié

- `POST /assistant/chat` en SSE : un échec du modèle arrive désormais après l'événement
  `conversation`, donc comme événement `error` (code `AI_UPSTREAM_ERROR`) suivi de `done`,
  et non plus comme réponse HTTP `502` en JSON. Le `429` budget reste du JSON ordinaire. Le
  mode JSON (sans `Accept: text/event-stream`) n'est pas touché.

## Corrigé

- Assistant : au tour suivant d'une conversation, le modèle connaît les actions qu'il a
  exécutées aux tours précédents (statut à jour, y compris une suppression confirmée ou
  refusée depuis). Il ne nie plus avoir créé une tâche.
- Assistant SSE : `conversation` est le tout premier événement, envoyé avant l'appel au
  modèle. La conversation peut s'afficher dans l'historique sans attendre la réponse.
- Assistant `create_task` : la tâche est créée dans un calendrier visible de l'usager, jamais
  dans le calendrier caché d'un projet. Sans calendrier normal, l'assistant répond que
  l'usager doit en créer un.
- Quota `max_calendars` : créer ou supprimer un projet ne consomme plus de place de
  calendrier (`403 QUOTA_EXCEEDED` injustifié auparavant).
