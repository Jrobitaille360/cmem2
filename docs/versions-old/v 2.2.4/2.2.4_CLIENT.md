# Migration client — v2.2.3 → v2.2.4

> **v2.2.4 ajoute la gestion des abonnements Premium par application.**

Ce document liste les changements que les applications clientes doivent prendre en compte
avant de consommer l'API en version 2.2.4.

---

## Changements cassants

**Aucun changement cassant dans cette version.**

La v2.2.4 est rétrocompatible avec la v2.2.3.

---

## Nouveautés (non cassantes) — Abonnements Premium

### Nouveau champ `subscriptions` dans `POST /auth/login`

La réponse de `/auth/login` contient désormais un objet `subscriptions` listant les
abonnements Premium actifs de l'utilisateur, indexés par `app_id`.

```json
{
  "token": "eyJhbGci...",
  "token_type": "Bearer",
  "expires_at": "2026-04-24 12:00:00",
  "user": { "id": 1, "name": "Alice", "email": "alice@example.com", "role": "UTILISATEUR" },
  "subscriptions": {
    "puzzle": {
      "is_premium": true,
      "show_ads":   false,
      "expires_at": "2026-05-09 12:00:00",
      "provider":   "stripe",
      "plan":       "monthly"
    }
  }
}
```

Si l'utilisateur n'a aucun abonnement actif, `subscriptions` est un objet vide `{}`.

### Nouveau champ `subscriptions` dans `GET /users/me`

La réponse de `GET /users/me` inclut également l'objet `subscriptions` avec la même structure.

---

### Nouveaux endpoints — `/subscription/*`

Tous ces endpoints nécessitent un JWT valide (`Authorization: Bearer <token>`).

#### Tableau récapitulatif

| Méthode | Endpoint | Description |
| --- | --- | --- |
| GET | `/subscription/status` | Statut Premium de toutes les applications |
| GET | `/subscription/status?app_id={app}` | Statut Premium d'une application précise |
| POST | `/subscription/verify` | Valider un achat et activer le Premium |
| DELETE | `/subscription/cancel` | Annuler un abonnement |

---

#### GET /subscription/status

Retourne les abonnements Premium actifs pour toutes les applications.

**Réponse `200` :**

```json
{
  "success": true,
  "data": {
    "subscriptions": {
      "puzzle": {
        "is_premium": true,
        "show_ads":   false,
        "expires_at": "2026-05-09 12:00:00",
        "provider":   "stripe",
        "plan":       "monthly"
      }
    }
  }
}
```

---

#### GET /subscription/status?app_id={app}

Retourne le statut Premium pour une application spécifique.

**Paramètre query :**

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `app_id` | string | oui | Identifiant de l'application (`puzzle`, `pomo`, `quiz`, …) |

**Réponse `200` — utilisateur Premium :**

```json
{
  "success": true,
  "data": {
    "app_id":     "puzzle",
    "is_premium": true,
    "show_ads":   false,
    "expires_at": "2026-05-09 12:00:00",
    "provider":   "stripe",
    "plan":       "monthly"
  }
}
```

**Réponse `200` — utilisateur sans abonnement :**

```json
{
  "success": true,
  "data": {
    "app_id":     "puzzle",
    "is_premium": false,
    "show_ads":   true,
    "expires_at": null,
    "provider":   null,
    "plan":       null
  }
}
```

> Utiliser `show_ads` (et non `is_premium`) comme indicateur d'affichage publicitaire.

---

#### POST /subscription/verify

Valide un achat côté provider et active (ou renouvelle) l'abonnement Premium.

**Body JSON :**

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `app_id` | string | oui | Identifiant de l'application |
| `provider` | string | oui | `stripe`, `google_play`, `apple`, `microsoft` |
| `product_id` | string | oui | Identifiant du produit côté provider |
| `plan` | string | oui | `monthly` ou `yearly` |
| `purchase_token` | string | non | Token Google Play / Apple |
| `stripe_sub_id` | string | non | ID de souscription Stripe |

**Réponse `200` :**

```json
{
  "success": true,
  "message": "Abonnement Premium activé",
  "data": {
    "app_id":     "puzzle",
    "is_premium": true,
    "show_ads":   false,
    "expires_at": "2026-05-10 12:00:00",
    "provider":   "stripe",
    "plan":       "monthly"
  }
}
```

**Erreurs :**

| Code | Cause |
| --- | --- |
| 400 | Champ requis manquant |
| 400 | `provider` invalide (valeurs acceptées : `stripe`, `google_play`, `apple`, `microsoft`) |
| 400 | `plan` invalide (valeurs acceptées : `monthly`, `yearly`) |
| 401 | JWT absent ou invalide |

---

#### DELETE /subscription/cancel

Annule l'abonnement actif pour une application.

> L'accès Premium reste actif jusqu'à la fin de la période payée.
> Après expiration, `is_premium` passe à `false` et `show_ads` à `true`.

**Body JSON :**

| Champ | Type | Requis | Description |
| --- | --- | --- | --- |
| `app_id` | string | oui | Identifiant de l'application à annuler |

**Réponse `200` :**

```json
{
  "success": true,
  "message": "Abonnement annulé — l'accès Premium reste actif jusqu'à la fin de la période payée"
}
```

---

## Valeurs `app_id` reconnues

| `app_id` | Application |
| --- | --- |
| `puzzle` | Puzzle CMEM2 |
| `pomo` | Pomodoro / Journal |
| `quiz` | Quiz interactif |

D'autres valeurs peuvent être ajoutées sans version majeure.

---

## Durées d'abonnement calculées côté serveur

| `plan` | Durée |
| --- | --- |
| `monthly` | +31 jours à partir de l'activation |
| `yearly` | +365 jours à partir de l'activation |

Les dates sont toujours en UTC (`Y-m-d H:i:s`).
