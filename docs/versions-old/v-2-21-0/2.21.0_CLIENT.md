# v2.21.0 — Changements visibles client

Fin de la commercialisation (plan accès sur approbation #269, Phases 4 et 6) : Stripe,
Google Play et l'ancien catalogue de plans sont retirés de l'API. L'accès dépend
uniquement de l'approbation du compte par l'admin et des modules cochés.

## BREAKING CHANGES

### Routes de paiement retirées → `404`

| Route | Remplacement |
| - | - |
| `POST /v2/billing/checkout`, `/portal`, `/webhook` | Aucun — plus de paiement |
| `GET\|DELETE /v2/subscriptions/stripe/*` | `GET /v2/access/status` |
| `POST\|GET\|DELETE /v2/subscriptions/playstore/*` | `GET /v2/access/status` |
| `GET\|POST\|DELETE /subscription/*` (legacy) | `GET /v2/access/status` |
| `GET /plans`, `GET /plans/{id}` | Aucun — plus de catalogue de prix |
| `GET\|POST /users/choose-plan` | Aucun |

### `GET /v2/access/status` : source unique « approval »

Contrat conservé (`is_premium`, `platforms` ou `platform`, `sources`). L'accès vaut `true`
sur **toutes** les plateformes (Android compris) pour un compte approuvé. `app_id` reste
requis mais n'influe plus sur le résultat.

```json
{
  "success": true,
  "data": {
    "is_premium": true,
    "platforms": { "android": true, "web": true, "windows": true },
    "sources": [
      { "provider": "approval", "status": "approved", "expires_at": null, "modules": ["contacts", "crm", "ged", "projet"] }
    ]
  }
}
```

Un compte `pending` ou `suspended` reçoit `403 ACCOUNT_PENDING` / `ACCOUNT_SUSPENDED`
(garde centrale, inchangée).

### Puzzle : premium = appareil lié à un compte approuvé

Les routes `/v2/puzzle/*` premium répondent toujours `403 SUBSCRIPTION_REQUIRED` quand
l'appareil n'est pas lié (`POST /puzzle/auth/link-device`) à un compte approuvé.

### Champ `plan`

`data.user.plan` (`GET /auth/me`) et `data.plan` (`GET /modules`,
`GET /groups/{id}/modules`) : `code` vaut `ami` (assigné par l'admin) ou `free` ; `source`
vaut `override` ou `default`. Plus de `source` `stripe` ni `group`. Le plan ne décide plus de
rien : disponibilité = modules cochés, caps = valeurs par défaut et surcharges.

### Suppression de compte

`DELETE /users/me` ne renvoie plus jamais `409 STRIPE_CANCEL_FAILED`.

### Vérification du courriel

`POST /users/verify-email` répond `{ "email_verified": true }`. Les champs
`plan_extended`, `new_plan_expiry_days` et `improved_limits` disparaissent, et le courriel
d'invitation aux plans payants n'est plus envoyé.

## Inchangé

- `/v2/devices/{android|web|windows}/*` (register, pseudonyme) : même contrat. La doc des
  appareils Android passe dans `docs/docs-api/webdevice/`.
- `PUT /users/{id}/plan-override` (`cmem_plan_override`, `ami`).
