# Déploiement production — v2.3.0

---

## Pré-requis

- v2.2.5 déjà en production (ou migration cumulative depuis v2.2.4)
- MySQL 5.7+ ou MariaDB 10.3+
- PHP 8.0+

---

## Checklist de déploiement

### 1. Sauvegarde préalable

```bash
mysqldump -u root cmem2_db > backup_before_2.3.0_$(date +%Y%m%d_%H%M%S).sql
```

### 2. Migration base de données

Appliquer dans cet ordre :

```bash
mysql -u root cmem2_db < docs/items/migrations/001_items_base.sql
```

Deux nouvelles tables sont créées :

- `items` — items utilisateur avec contrôle d'accès
- `item_user_access` — liste de partage par item

> La migration est **non destructive** : aucune table existante n'est modifiée.

### 3. Déploiement du code

```bash
git pull origin main
# Pas de composer install requis — aucune nouvelle dépendance
```

### 4. Vérification post-déploiement

```bash
# Sanity check — le plugin Items se charge
curl -s https://votre-domaine.com/items \
  -H "Authorization: Bearer <token_valide>" | jq .

# Attendu : {"success":false,"message":"Utilisateur non authentifié",...}
# (ou 200 si le token est valide)
```

```bash
# Tables présentes
mysql -u root cmem2_db -e "SHOW TABLES LIKE 'item%';"
# items
# item_user_access
```

### 5. Tests fonctionnels

```bash
php private/tests_mine/test_items.php
# Attendu : 84/84 OK
```

---

## Rollback

En cas de problème :

```bash
# Supprimer les nouvelles tables (sans impact sur le reste)
mysql -u root cmem2_db -e "
  SET foreign_key_checks=0;
  DROP TABLE IF EXISTS item_user_access;
  DROP TABLE IF EXISTS items;
  SET foreign_key_checks=1;
"

# Revenir au commit précédent
git checkout v2.2.5
```

---

## Stratégie de backup

Les tables `items` et `item_user_access` sont incluses dans les dumps complets existants.
Aucune modification de la configuration cron n'est requise.

---

## Changements d'infrastructure

**Aucun.** Pas de nouveau service, port, variable d'environnement ou dépendance Composer.
