# v2.4.1 — Changements visibles client

## Nouveautés

### Accessibilité des fichiers (public / private)

Les fichiers uploadés ont désormais un champ `accessibility` :

| Valeur | Comportement |
| - | - |
| `private` (défaut) | Seuls le déposant et un administrateur peuvent télécharger / consulter les métadonnées |
| `public` | Tout utilisateur avec un JWT valide peut télécharger / consulter les métadonnées |

#### Impact sur les endpoints existants

- **`POST /files`** — nouveau champ FormData optionnel `accessibility` (`public` ou `private`).
  Retourne 422 si la valeur est invalide. Inclut `accessibility` dans la réponse 201.
- **`GET /files/{id}`** — retourne désormais `403` si le fichier est `private` et que
  l'appelant n'est ni propriétaire ni administrateur.
- **`GET /files/{id}/info`** — même règle d'accessibilité que le téléchargement.
  Inclut `accessibility` dans la réponse.
- **`GET /files/user/{user_id}`** — inclut `accessibility` dans chaque objet de la liste.

#### Nouvel endpoint

```http
PATCH /files/{id}/accessibility
Authorization: Bearer {jwt_token}
Content-Type: application/json

{ "accessibility": "public" }
```

Réponse `200` : `{ "file_id": 42, "accessibility": "public" }` \
Erreurs : `403` (non-propriétaire/non-admin), `404` (introuvable), `422` (valeur invalide).

## BREAKING CHANGES

Aucun breaking change. Les fichiers existants obtiennent `accessibility = 'private'`
par défaut via la migration SQL — comportement identique à l'ancienne logique (propriétaire ou admin uniquement).
