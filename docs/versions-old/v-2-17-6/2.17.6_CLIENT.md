# v2.17.6 — Changements visibles client

## Corrigé

### Import JSON de projet — id numériques temporaires

`POST /projets/projects/{id}/import.json[/confirm]` : une tâche dont l'`id` est numérique
mais absent du projet cible (ex. fichiers du module Assistant, id 9001-9113) est créée et ses
`dependsOn` / `parentId` sont remappés vers les nouveaux id réels. Auparavant, ces liens
étaient perdus sans erreur.

### Validation stricte de l'import

`422` au dry-run comme au confirm, sans écriture, si :

- `dependsOn` n'est pas un tableau d'objets `{taskId, type, lagDays}` (ex. `[9101]`) ;
- `type` est hors `FS`, `SS`, `FF`, `SF`, ou `lagDays` n'est pas un entier ;
- un `id` apparaît deux fois dans le fichier ;
- `parentId` ou `dependsOn[].taskId` ne pointe ni vers une tâche du fichier ni vers une tâche
  du projet cible.

## Ajouté

- Dry-run : `liens: [{de, vers, type}]` (`type: "parent"` pour la hiérarchie) et
  `doublonsTitre: [string]` (titres à créer déjà présents dans le projet — un réimport d'un
  fichier à id temporaires recrée les tâches).
- Confirm : `liens` (nombre de liens écrits).

## BREAKING CHANGES

Aucun pour un client conforme au contrat. Un fichier avec `dependsOn` mal formé ou une
référence hors projet, auparavant accepté silencieusement (liens ignorés), reçoit désormais
un `422`. Le contournement cmem_web (id texte `WEB-01`, `dependsOn` objets) reste compatible.
