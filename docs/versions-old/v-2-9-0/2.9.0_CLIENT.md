# cmem2 API — v2.9.0 (2026-07-19)

Changements visibles pour les applications clientes (cmem-web, Flutter).

## Nouveautés

### Calendriers (ICS)

- **Partage de calendrier avec un groupe** — `POST /calendars/{id}/share` accepte désormais
  `group_id` en plus de `user_id`/`email` : tous les membres du groupe héritent de la
  permission (lecture ou écriture). `GET`/`DELETE /calendars/{id}/share` supportent aussi
  `group_id`.
- **Étiquettes (tags) de calendrier** — `GET/POST /calendars/{id}/tags`,
  `PUT/DELETE /calendars/{id}/tags/{tagId}` : étiquettes scopées par calendrier, visibles et
  modifiables par tout membre partagé, avec cascade à la suppression du calendrier.
- **Corbeille récupérable** — événements/tâches/journaux supprimés peuvent être restaurés.
- **Expansion d'occurrences à la demande** — nouvel endpoint additif pour obtenir les
  occurrences RRULE sur une plage donnée sans dépendre de la table pré-calculée.

### Administration

- **Rôle `SUPERADMINISTRATEUR`** — nouvelle matrice d'autorité admin/superadmin. Voir
  `docs/core/GUIDE.md` pour le détail des permissions.
- **`GET /users?include_deleted=1`** — retrouver les comptes soft-deleted (admin/superadmin
  seulement).
- **`PUT /users/{id}/plan-override`** — assignation manuelle du plan « Ami » (superadmin
  seulement).

### Documentation publique

- **`GET /entrypoints`** et **`GET /entrypoints/{module}`** — documentation JSON des endpoints
  exposée publiquement, sans authentification.

### Quiz

- **`show_question_to_player`** — nouveau paramètre de quiz : masquer la question au joueur
  (vue hôte uniquement) si désactivé.

## Corrections

- **Stripe** — `metadata` (`user_id`, `app_id`) manquant au niveau racine de la session
  checkout provoquait un échec silencieux de création de `stripe_subscriptions`. Corrigé.

## Aucun changement cassant (breaking change)

Tous les changements sont additifs ou correctifs — aucune modification de contrat existant.
