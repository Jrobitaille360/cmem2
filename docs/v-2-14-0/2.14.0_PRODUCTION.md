# cmem2_API v2.14.0 — Checklist de déploiement production

Date : 2026-08-04
Cible : `cmem2.journauxdebord.com`

## 1. Migrations SQL

Trois migrations, toutes additives. **Déjà appliquées en dev et en prod le 2026-08-04.**

| Fichier | Effet | Statut |
| - | - | - |
| `docs/v-2-14-0/20260803_journaux_e2e.sql` | `calendar_journals` : `summary` → `VARCHAR(2000)`, `description` → `MEDIUMTEXT`, + `enc_alg`, `enc_iv` | Appliquée |
| `docs/v-2-14-0/20260803_user_e2e_keys.sql` | Nouvelle table `user_e2e_keys` | Appliquée |
| `docs/v-2-14-0/20260804_e2e_taches_contacts.sql` | `calendar_todos` : `title` → `VARCHAR(2000)`, `description` → `MEDIUMTEXT`, + `enc_alg`, `enc_iv` ; `contacts` : + `enc_alg`, `enc_iv`, `enc_payload` | Appliquée |

Aucun impact sur les lignes existantes : les nouvelles colonnes sont `NULL` par défaut et les
changements de type sont des élargissements — aucune troncature possible.

Installation neuve : `docs/v-2-14-0/build_DB-v-2.14.0.sql`.

Vérification que les migrations sont bien en place :

```sql
SHOW COLUMNS FROM calendar_todos     LIKE 'enc_%';   -- enc_alg, enc_iv
SHOW COLUMNS FROM calendar_journals  LIKE 'enc_%';   -- enc_alg, enc_iv
SHOW COLUMNS FROM contacts           LIKE 'enc_%';   -- enc_alg, enc_iv, enc_payload
SHOW TABLES LIKE 'user_e2e_keys';
```

## 2. Variables `.env` à ajouter

```dotenv
APP_VERSION=2.14.0
```

Aucune autre variable. Le chiffrement n'introduit **aucun secret côté serveur** — c'est le principe
même du bout en bout.

## 3. Fichiers de configuration serveur

Aucun changement (`.htaccess`, `user.ini` inchangés depuis la v2.13.0).

⚠️ Les corps de requête peuvent devenir plus gros : un `description` chiffré accepte jusqu'à
16 000 000 caractères et `enc_payload` la même borne. Vérifier que `post_max_size` du serveur
(`105M` depuis la v2.13.0) reste cohérent avec l'usage réel du client. Un dépassement côté PHP se
traduit par un corps vide, pas par une erreur applicative explicite.

## 4. Déploiement

```powershell
.\private\deploy.ps1 -Target prod
```

Le script transfère `index.php`, `src/`, `.htaccess`, `composer.*`, puis exécute
`composer install --no-dev --optimize-autoloader` sur le serveur.

Si composer est cassé côté cPanel :

```powershell
.\private\deploy.ps1 -Target prod -LocalComposerInstall
```

## 5. Crons

Aucun changement. Le cron push (`DueScanner`) utilisait déjà un libellé générique : il ne lit ni
titre de tâche, ni nom de contact, donc jamais un blob chiffré.

## 7. Suivi client

Prévenir `cmem_web` que les trois directives de la phase 3 sont livrées — voir
`docs/v-2-14-0/2.14.0_CLIENT.md`. Aucun contrat rompu : les champs `enc_*` sont optionnels et
valent `null` pour tout contenu existant.

## 8. Retour arrière

Le code peut être remis à la version précédente sans toucher au schéma :

```bash
git checkout v2.13.0
powershell private/deploy.ps1 -Target prod
```

Les colonnes `enc_*` resteront en base, inertes — l'ancien code les ignore. **Ne pas les supprimer**
si des contenus chiffrés ont déjà été écrits : `DROP COLUMN enc_payload` ou `DROP TABLE
user_e2e_keys` détruirait irrémédiablement des données que personne, serveur compris, ne peut
reconstituer.
