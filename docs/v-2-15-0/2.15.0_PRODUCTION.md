# cmem2_API v2.15.0 — Checklist de déploiement production

Date : 2026-08-11
Cible : `cmem2.journauxdebord.com`

## 1. Migrations SQL

Deux migrations. **À appliquer avant le déploiement du code**, dans cet ordre (l'UPDATE dépend de
l'ancienne sémantique, la CREATE TABLE est indépendante) :

| Fichier | Effet | Type |
| - | - | - |
| `docs/v-2-15-0/20260804_occurrence_modified_empty_to_null.sql` | `event_occurrences` : `''` → `NULL` sur `modified_location` / `modified_description` | Données (UPDATE) |
| `docs/v-2-15-0/20260804_traque_roles.sql` | Nouvelle table `traque_roles` | Additive (CREATE TABLE) |

Installation neuve : `docs/v-2-15-0/build_DB-v-2.15.0.sql`.

Vérification post-migration :

```sql
SELECT COUNT(*) FROM event_occurrences WHERE modified_location = '' OR modified_description = '';
-- attendu : 0

SHOW TABLES LIKE 'traque_roles';
```

## 2. Variables `.env` à ajouter

```dotenv
APP_VERSION=2.15.0
```

Aucune autre variable serveur nouvelle. Le proxy IA réutilise `ANTHROPIC_API_KEY` /
`AI_SUMMARIZE_MODEL`, déjà déployés en dev depuis la directive `ai-proxy` (à confirmer présents sur
`cmem2.journauxdebord.com` avant bascule — sans quoi `POST /ai/summarize` répond `502`).
