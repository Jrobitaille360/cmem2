# cmem2_API v2.15.0 — Changements visibles côté client

Date : 2026-08-11

## BREAKING CHANGES

Aucun. Tous les changements sont additifs ou corrigent un comportement déjà cassé.

## Ce que la version apporte

Six directives inter-projets traitées, sans rupture de contrat.

## 1. Push web — livraison Android fiable

> Directive `20260810_121500_cmem_web_vers_cmem2_API__urgency-high-web-push`

`WebPushService::sendToOwner()` envoie désormais l'entête `Urgency: high` à FCM. Aucun changement
côté client : les notifications déjà reçues arrivent simplement plus vite (secondes, plus minutes à
heures) sur Android sous App Standby / Doze.

## 2. Calendrier — `null` efface, champ absent laisse inchangé

> Directive `20260729_174600_cmem_web_vers_cmem2_API__null-effacement-explicite-put-evenement`

`PUT /calendars/{cid}/events/{eid}` distingue désormais « absent » de « null » sur `location`,
`description`, `color` et `recurrence_rule`.

| Valeur envoyée | Effet |
| - | - |
| Champ absent | Colonne inchangée |
| `null` | Colonne mise à `NULL` (effacement explicite) |
| Chaîne vide | Normalisée en `NULL` |

Aucun `422` n'est renvoyé sur `null` pour ces champs. `recurrence_rule: null` fait cesser la
récurrence sans purger les exceptions déjà posées — elles redeviennent actives si une `RRULE` est
reposée plus tard.

## 3. Calendrier — vider le lieu ou la description d'une seule occurrence

> Directive `20260729_174500_cmem_web_vers_cmem2_API__effacement-lieu-description-occurrence`

Trois états désormais distincts sur `modified_location` et `modified_description` d'une occurrence :

| Valeur | Effet |
| - | - |
| `NULL` | N'écrase pas le champ — hérite de l'événement parent |
| `''` | Effacement volontaire (l'occurrence n'affiche rien) |
| texte | Remplace la valeur du parent pour cette occurrence |

Sémantique volontairement inverse de celle de l'événement (§2), où `NULL` signifie déjà
« effacer ». Un `null` explicite en écriture est désormais accepté et normalisé en `''` ; un champ
absent ne touche à rien. Même comportement sur `scope=only_this`, `all_future` et `all`.

⚠️ Migration de données appliquée avant déploiement : toute chaîne vide déjà en base sous
l'ancienne sémantique (« non modifié ») est repassée à `NULL`.

## 4. Traque — rôles de jeu (`gm`, `traque_admin`)

> Directive `20260605_161757_traque_vers_cmem2_API__table-traque-roles-et-endpoints-admin-gm` (partiel)

Nouveaux rôles orthogonaux aux rôles CMEM2 : un compte peut être à la fois joueur et Maître de Jeu.

- `POST /traque/admin/roles/grant`, `DELETE /traque/admin/roles/revoke`,
  `GET /traque/admin/roles/log` — réservés `traque_admin`
- `POST /traque/players/me/levelup` accorde automatiquement `gm` au niveau 15 et retourne
  `gm_granted`
- Hors périmètre pour l'instant : endpoints de secteur MJ et CRUD de contenu (monstres, PNJ,
  portails, dimensions) — cinq tables non définies à ce jour

## 5. Proxy IA — `POST /ai/summarize`

> Directive `20260810_140000_cmem_web_vers_cmem2_API__ai-proxy`

Nouvel endpoint : résumé d'agenda sur une période, déclenché manuellement par l'usager.

- Nécessite le module `ia` disponible (plan `monthly`/`yearly`/`ami`) et activé
  (`PATCH /modules/ia`)
- Le corps du journal n'est jamais transmis au modèle — seules des métadonnées bornées assemblées
  côté client (`period`, `items[]` : titre, date, tags, statut)
- Quota décompté avant l'appel modèle ; `429 AI_QUOTA_EXCEEDED` si déjà épuisé
- `502` si l'appel modèle échoue après décompte du quota (quota tout de même consommé)

## Hors périmètre client

`AUTH_TEST_CODE` (code OTP fixe en développement) ne concerne que la suite Playwright de `jdb` —
inactif hors `APP_ENV=development`, aucun impact sur les clients de production.

## Contrat inchangé pour tout le reste

Aucun champ retiré, aucune signature d'endpoint modifiée hors des cas listés ci-dessus.
