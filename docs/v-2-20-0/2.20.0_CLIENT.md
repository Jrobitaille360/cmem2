# v2.20.0 — Changements visibles client

## BREAKING CHANGES

### Rappels d'événement : seul le type `EMAIL` est accepté

`POST /calendars/{id}/events` et `PUT /calendars/{id}/events/{eventId}` : un rappel
`notifications[]` d'un autre type que `EMAIL` (`DISPLAY`, `notification`, `AUDIO`) répond
`422` (directive cmem_web #440). Avant, il était enregistré mais jamais envoyé.

```json
{
  "success": false,
  "message": "Rappel push par élément pas encore disponible : seuls les rappels EMAIL sont acceptés",
  "errors": {
    "code": "REMINDER_CHANNEL_UNSUPPORTED",
    "field": "notifications.0.type",
    "type": "DISPLAY"
  }
}
```

L'import `.ics` reste permissif : un `VALARM ACTION:DISPLAY` est conservé sans envoi et
l'import réussit. Les événements existants ne sont pas modifiés.

### Caps de ressources : fin du lien avec le plan Stripe

Les quotas (`403` avec `errors.code` = `QUOTA_EXCEEDED`, contrat inchangé) et
`GET /auth/me` (`data.user.plan.features`) ne dépendent plus du plan Stripe ni de
`cmem_plan_override`. Tous les comptes reçoivent les caps par défaut, plus larges que
l'ancien plan gratuit :

| Clé | Défaut | Niveau |
| - | - | - |
| `max_calendars` | 25 | utilisateur |
| `max_journals` | 2500 | utilisateur |
| `max_tasks` | 5000 | utilisateur |
| `max_devices` | 5 | utilisateur |
| `max_storage_mb` | 2000 | utilisateur |
| `max_groups` | 10 | utilisateur |
| `max_contacts` | 2000 | utilisateur |
| `max_group_members` | 50 | groupe |

Aucun compte ne perd de capacité. Nouveau contrôle : `max_group_members` est vérifié à
l'ajout direct d'un membre (`POST /groups/{id}/members/{user_id}`) et à l'acceptation d'une
invitation de groupe (`403` « Quota de membres du groupe atteint »).

## Ajouté

### Administration des caps (ADMINISTRATEUR+)

| Méthode | Route | Rôle |
| - | - | - |
| `GET` | `/caps/defaults` | Caps par défaut et niveau de chaque clé |
| `GET` | `/users/{id}/caps` | Surcharges et caps effectifs d'un utilisateur |
| `PUT` | `/users/{id}/caps` | Remplace toutes les surcharges d'un utilisateur |
| `GET` | `/groups/{id}/caps` | Surcharges et caps effectifs d'un groupe |
| `PUT` | `/groups/{id}/caps` | Remplace toutes les surcharges d'un groupe |

Corps du `PUT` : `{"caps": {"max_contacts": 5000, "max_calendars": null}}`. Une valeur
`null` = illimité ; `{}` remet tout au défaut. Clé inconnue ou du mauvais niveau, valeur
négative ou non entière : `422`. Utilisateur ou groupe absent : `404`.

Détail : `docs/docs-api/access/API_ACCESS_ENDPOINTS.json`, section `caps`.

## Corrigé

- Rappels courriel des événements récurrents : chaque occurrence reçoit son rappel, pas
  seulement la première (directive cmem_web #438). Les occurrences annulées ne sont pas
  rappelées ; les occurrences déplacées le sont à leur nouvelle heure. Le courriel affiche la
  date et l'heure réelles de l'occurrence.
- Rappels saisis avec la clé `minutes` au lieu de `minutes_before` : maintenant envoyés.
