# v2.26.1 — Changements visibles client

Version de correctifs : aucune route ajoutée ni retirée, aucun changement de schéma.

## Changement de comportement

- `POST /auth/send-code` et `POST /auth/restore-account` répondent désormais `500`
  « Erreur lors de l'envoi du code » (`success: false`) quand le courriel contenant le code
  n'a pas pu partir (SMTP ou `mail()` en échec). Avant, l'API répondait `200` « Code envoyé »
  alors qu'aucun code n'arrivait (task #534, directive jesaisquand).
- Action côté client : sur `500`, afficher l'erreur et proposer de réessayer plus tard au lieu
  d'ouvrir l'écran de saisie du code. Les autres réponses (`200` générique, `403`, `409`,
  `429`) sont inchangées.

## Incident corrigé

- Du 2026-11-20 au 2026-11-22 12:56, aucun code OTP n'est parti de la production
  (`535 Incorrect authentication data` sur `mail.journauxdebord.com` après un changement de
  mot de passe de la boîte d'envoi). Configuration corrigée le 2026-11-22.

## BREAKING CHANGES

- Aucun. Le `500` est un nouveau cas d'erreur sur un échec qui était auparavant masqué.
