# cmem2 API — v2.11.0 — Checklist déploiement

Date : 2026-07-26
Cibles : **production** (`cmem2.journauxdebord.com`) et **dev** (`dev-cmem2.journauxdebord.com`)

> ⚠️ **Pas de `composer` sur le serveur.** Les dépendances sont déjà présentes dans
> `vendor/` déployé. Ne pas exécuter `composer install` en prod ni en dev.
> Cette version ajoute la dépendance `minishlink/web-push ^9` — **le `vendor/` déployé
> doit être celui régénéré localement**, sinon les routes `/push/*` échouent au chargement.

## 1. Migrations SQL

Sept migrations à appliquer, **dans cet ordre** (dépendances FK) — déjà appliquées sur
**dev-cmem**, à faire sur **prod** :

```sql
SET foreign_key_checks = 0;
SOURCE docs/v-2-11-0/20260724_interactions.sql;       -- interaction, contacts.optout_courriel
SOURCE docs/v-2-11-0/20260724_interactions_crm.sql;   -- interaction : rdv, resume, soft-delete, pièce jointe
SOURCE docs/v-2-11-0/20260724_opportunite.sql;        -- opportunite
SOURCE docs/v-2-11-0/20260724_links_ged.sql;          -- links.src_type/dst_type += 4 types
SOURCE docs/v-2-11-0/20260726_contacts_relance.sql;   -- contacts : date_relance, motif_relance, relance_faite_le
SOURCE docs/v-2-11-0/20260726_users_timezone.sql;     -- users.timezone
SOURCE docs/v-2-11-0/20260726_web_push.sql;           -- push_subscriptions, notification_prefs, push_notification_log
SET foreign_key_checks = 1;
```

Nouvelle base à partir de zéro : `docs/v-2-11-0/build_DB-v-2.11.0.sql` (intègre les sept).

Tables créées : `interaction`, `opportunite`, `push_subscriptions`, `notification_prefs`,
`push_notification_log`.
Colonnes ajoutées : `users.timezone` ; `contacts.optout_courriel`, `contacts.date_relance`,
`contacts.motif_relance`, `contacts.relance_faite_le`.
ENUM étendus : `links.src_type`/`dst_type` (+ `file`, `contact`, `interaction`, `opportunite`),
`interaction.type` (+ `rdv`).

## 2. Variables `.env`

- `APP_VERSION=2.11.0`
- **Nouvelles clés Web Push** — générer la paire sur le serveur cible avec
  `php src/push/generate_vapid.php`, puis renseigner :
  - `VAPID_PUBLIC_KEY=...`
  - `VAPID_PRIVATE_KEY=...`
  - `VAPID_SUBJECT=mailto:support@journauxdebord.com`
  - `PUSH_GENERIC_TITLE=Rappel`
  - `PUSH_TTL_SECONDS=86400`

> Les clés VAPID sont **propres à chaque environnement**. Changer la paire invalide toutes
> les subscriptions déjà enregistrées — les clients devront se réabonner.

- Vérifier `LOG_DIR=logs/` (relatif). Un chemin absolu est désormais accepté et respecté ;
  auparavant il était concaténé à la racine du projet et les journaux partaient dans un
  dossier imbriqué.

## 3. Crons

- **Ajouter** l'envoi des notifications push, toutes les 5 minutes :

  ```cron
  */5 * * * * /usr/local/bin/php /home/lmdkhdg5/cmem2.journauxdebord.com/src/push/send_push_notifications.php >> /home/lmdkhdg5/logs/cron_push.log 2>&1
  ```

  Options disponibles pour un essai à blanc : `--dry-run`, `--verbose`, `--batch=`,
  `--user=`, `--now=`.
- Aucune autre modification crontab requise.

## 4. Vérifications post-déploiement

- [ ] `GET /` répond `200` et expose `version = 2.11.0`.
- [ ] `GET /push/vapid-public-key` (JWT) → `200` avec une clé de 87 caractères.
- [ ] `POST /push/subscribe` puis `DELETE /push/subscribe` → `201` puis `204`.
- [ ] `GET /push/preferences` (JWT) → `200`, `enabled = false` par défaut.
- [ ] `php src/push/send_push_notifications.php --dry-run --verbose` s'exécute sans erreur.
- [ ] `GET /users/me` expose `timezone` ; `PUT /users/me` avec `timezone=Europe/Paris` → `200`,
      avec `timezone=Pas/Un/Fuseau` → `422`.
- [ ] `GET /opportunites` (JWT) → `200`.
- [ ] `GET /contacts/{id}/interactions` (JWT) → `200`.
- [ ] `POST /links` avec `src_type=file` → `201`.
- [ ] `POST /contacts` avec `date_relance` → `201`, relecture `GET /contacts/{id}` conforme.
- [ ] Les journaux du jour apparaissent bien dans `logs/app-YYYY-MM-DD.log` à la racine du
      projet, et non dans un dossier imbriqué.
