# Déploiement production — v2.2.4

Checklist à suivre dans l'ordre pour mettre en production la version 2.2.4.

> **v2.2.4 ajoute la gestion des abonnements Premium par application.**
> Une migration SQL est requise.

---

## 1. Migration SQL

### 1a. Table `subscriptions`

Exécuter le script de migration :

```bash
mysql -u <user> -p <database> < docs/core/migrations/20260409_subscriptions.sql
```

Ou copier-coller directement :

```sql
CREATE TABLE IF NOT EXISTS subscriptions (
    id          INT(11) AUTO_INCREMENT PRIMARY KEY,
    user_id     INT(11) NOT NULL,
    app_id      VARCHAR(50) NOT NULL COMMENT 'ex: puzzle, pomo, quiz',
    provider    ENUM('stripe','google_play','apple','microsoft') NOT NULL,
    status      ENUM('active','cancelled','expired','past_due') NOT NULL DEFAULT 'active',
    plan        ENUM('monthly','yearly') NOT NULL,
    product_id  VARCHAR(255) NOT NULL,
    started_at  DATETIME NOT NULL,
    expires_at  DATETIME NOT NULL,
    purchase_token VARCHAR(500) DEFAULT NULL,
    stripe_sub_id  VARCHAR(255) DEFAULT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uq_user_app_provider (user_id, app_id, provider),
    KEY idx_expires_status (expires_at, status),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Ce script crée 1 nouvelle table :

| Table | Description |
| --- | --- |
| `subscriptions` | Abonnements Premium par utilisateur et par application |

> La migration utilise `CREATE TABLE IF NOT EXISTS` — elle est idempotente et sans risque sur un serveur déjà à jour.

## 2. Variables d'environnement

**Aucune variable d'environnement nouvelle requise pour cette version.**

Le `.env` de production issu de la v2.2.3 est compatible sans modification.

---

## 3. CRON — expiration automatique des abonnements

Ajouter la tâche planifiée suivante pour expirer les abonnements dépassés et envoyer
des emails de notification :

```bash
crontab -e
```

Ajouter la ligne :

```cron
0 3 * * * php /var/www/html/cmem2_API/src/cron/expire_subscriptions.php >> /var/log/cmem2_expire_subscriptions.log 2>&1
```

> Le script s'exécute chaque nuit à 03:00 et expire tous les abonnements dont `expires_at < NOW()`.

## 4. Déploiement du code

```bash
git fetch origin
git reset --hard origin/main
composer install --no-dev --optimize-autoloader
```

> `reset --hard` n'affecte pas les fichiers ignorés par git (`.env`, logs, `private/`, etc.).

### Prérequis côté client

La v2.2.4 ne contient **aucun changement cassant**.
Les clients en v2.2.3 continuent de fonctionner sans modification.

Les nouveaux endpoints sont documentés dans `docs/v 2.2.4/2.2.4_CLIENT.md`.

## 5. Vérifications post-déploiement

### Abonnements Premium

```text
POST /auth/login  (email + password)
  → 200, réponse contient "subscriptions": {}

GET  /subscription/status
  → 401 sans JWT
  → 200 avec JWT, "subscriptions": {}

GET  /subscription/status?app_id=puzzle
  → 200, "is_premium": false, "show_ads": true

POST /subscription/verify  (app_id, provider, product_id, plan)
  → 200, "is_premium": true, "show_ads": false, "expires_at" renseigné

DELETE /subscription/cancel  (app_id)
  → 200, message de confirmation

POST /subscription/verify  (provider invalide)
  → 400

GET  /users/me
  → 200, réponse contient "subscriptions": {}
```

### CRON

```bash
php src/cron/expire_subscriptions.php
# → "Abonnements expirés : 0" (ou N si des entrées ont expiré)
```

## 6. Rollback

La migration est additive (`CREATE TABLE`).
Un retour au tag v2.2.3 ne nécessite pas d'annuler la migration —
la table `subscriptions` est ignorée par le code v2.2.3.

Si une annulation complète est nécessaire :

```sql
ALTER TABLE subscriptions DROP FOREIGN KEY subscriptions_ibfk_1;
DROP TABLE IF EXISTS subscriptions;
```

Puis retour au code :

```bash
git reset --hard v2.2.3
composer install --no-dev --optimize-autoloader
```

> Supprimer également la tâche CRON ajoutée à l'étape 3.
