## Nouveau

### Suivi du temps par tâche (sessions start/stop)

Directive : `20260814_143000_cmem_web_vers_cmem2_API__time-tracking-sessions.md` (D3)

Sessions de temps rattachées à une tâche (VTODO), démarrées/arrêtées explicitement (pas un
compteur cumulé). Un seul minuteur actif à la fois par usager, tous calendriers/tâches confondus.

| Méthode | Route |
| - | - |
| `POST` | `/calendars/{id}/todos/{todoId}/time-sessions/start` |
| `GET` | `/calendars/{id}/todos/{todoId}/time-sessions` |
| `GET` | `/time-sessions/active` |
| `PATCH` | `/time-sessions/{id}/stop` |
| `PUT`\|`PATCH` | `/time-sessions/{id}` |
| `DELETE` | `/time-sessions/{id}` |

- `409 ACTIVE_SESSION_EXISTS` (avec `errors.active_session_id`) si une session est déjà en cours.
- `note` chiffrable de bout en bout (`enc_alg`/`enc_iv`), même convention que `title`/`description`
  des VTODO.
- Démarrer/lister suit la permission de lecture du calendrier ; arrêter/modifier/supprimer est
  réservé au propriétaire de la session.
- Pas de gating par plan (`tenant_modules`) — disponible sur tous les plans, comme les tâches
  elles-mêmes.
- Pas de corbeille : `DELETE` est définitif.

Référence complète : [docs/ics/GUIDE.md](../ics/GUIDE.md#endpoints--sessions-de-temps),
[docs/ics/API_ICS_ENDPOINTS.json](../ics/API_ICS_ENDPOINTS.json).
