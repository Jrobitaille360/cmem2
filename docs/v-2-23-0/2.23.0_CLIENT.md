# v2.23.0 — Changements visibles client

Nouveau module **Assistant** : chat avec Claude qui lit et modifie les tâches de l'usager et
leurs rappels. Aucune rupture : les clients existants n'ont rien à changer. Référence
complète : `docs/docs-api/assistant/GUIDE.md` et `API_ASSISTANT_ENDPOINTS.json`.

## BREAKING CHANGES

Aucun.

`GET /modules` (et `GET /groups/{id}/modules`) retourne désormais **9** modules au lieu de 8 :
la clé `assistant` s'ajoute (`available: false`, `enabled: false` tant qu'elle n'est pas cochée).
Un client qui supposait une liste fixe de 8 clés doit accepter la nouvelle.

## Ajouté

### Activation

| Étape | Qui | Route |
| - | - | - |
| Cocher le module `assistant` | admin | `PUT /users/{id}/modules` |
| Activer le module | usager | `PATCH /modules/assistant {"app_id": "cmemweb", "enabled": true}` |
| Donner son consentement (Loi 25) | usager | `POST /assistant/consent` |

### Routes `/assistant/*` (JWT)

| Méthode | Route | Rôle |
| - | - | - |
| `GET` / `POST` / `DELETE` | `/assistant/consent` | État, accord, retrait du consentement |
| `POST` | `/assistant/chat` | Message → réponse JSON, ou flux SSE avec `Accept: text/event-stream` |
| `GET` / `DELETE` | `/assistant/conversations` | Liste / suppression de tout l'historique |
| `GET` / `DELETE` | `/assistant/conversations/{id}` | Détail / suppression d'une conversation |
| `GET` | `/assistant/actions` | Journal des actions (`?status=PENDING`) |
| `POST` | `/assistant/actions/{id}/confirm` | Exécute une suppression proposée |
| `POST` | `/assistant/actions/{id}/reject` | Refuse une suppression proposée |
| `GET` | `/assistant/usage` | Budget IA du mois + part de l'Assistant |

### Flux SSE de `POST /assistant/chat`

Événements dans l'ordre : `conversation` → `delta` (texte au fil de l'eau) et `tool` (action
effectuée ou proposée) → `error` (rare) → `done` (même objet que la réponse JSON). `EventSource`
ne fait pas de `POST` : utiliser `fetch()` et lire `response.body`.

### Suppressions

L'assistant ne supprime jamais rien directement : il crée une action `PENDING`. Le client
affiche une confirmation puis appelle `confirm` ou `reject`.

### Nouveaux codes d'erreur

| HTTP | Code | Cause |
| - | - | - |
| 403 | `MODULE_NOT_AVAILABLE` | Module `assistant` non coché ou non activé (`available`, `enabled` dans `errors`) |
| 403 | `ASSISTANT_CONSENT_REQUIRED` | Consentement absent ou retiré |
| 409 | `ACTION_NOT_PENDING` | Action déjà confirmée ou refusée |
| 429 | `AI_BUDGET_EXCEEDED` | Budget IA atteint (`scope: user` ou `global`) — budget commun avec `/ai/summarize` |
| 502 | `AI_UPSTREAM_ERROR` | Échec du modèle (non facturé) |
| 503 | `AI_NOT_CONFIGURED` | Clé IA absente côté serveur |
