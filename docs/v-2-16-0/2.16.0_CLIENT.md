# cmem2_API v2.16.0 — Changements visibles côté client

Date : 2026-08-14

## BREAKING CHANGES

Aucun. Tous les changements sont additifs.

## Ce que la version apporte

Trois directives inter-projets traitées, plus la résolution d'un incident post-déploiement
v2.15.0 (proxy IA, config uniquement).

## 1. Nouveau — Réservation publique (`booking`)

> Directive `20260813_163000_cmem_web_vers_cmem2_API__booking-public.md`

Un usager sur plan payant (`monthly`/`yearly`/`team`/`ami`) peut publier une page de réservation
sans authentification : un invité externe choisit un créneau, l'événement apparaît directement
dans le calendrier de l'hôte.

- `GET/PUT/DELETE /booking/page` (hôte, JWT) — configuration : calendrier, durée, fenêtres de
  disponibilité, gabarit de titre
- `GET /booking/public/{slug}[/slots]`, `POST /booking/public/{slug}/book`,
  `POST /booking/public/cancel/{token}` — publics, sans authentification
- Réservation auto-confirmée, écriture atomique (un seul gagnant en cas de double clic simultané
  sur le même créneau), annulation par lien à jeton envoyé par courriel
- Voir [docs/booking/GUIDE.md](../booking/GUIDE.md) pour le détail complet

## 2. Plan équipe — facturation Stripe portée par un groupe

> Directive `20260813_143000_cmem_web_vers_cmem2_API__plan-equipe.md`

- Nouveau tier `team` (mensuel seul en v1) — un groupe peut porter son propre abonnement Stripe
  au lieu de facturer chaque membre individuellement
- `POST /v2/billing/checkout`/`portal` et `DELETE /v2/subscriptions/stripe` acceptent un
  `group_id` optionnel (réservé aux admins du groupe pour l'écriture)
- Plan effectif d'un membre = meilleur de (plan perso, plan de chaque groupe actif) — `GET
  /auth/me` expose `source: "group"` et `group_id` quand un groupe l'emporte
- `GET/PATCH /groups/{id}/modules[/{key}]` — modules activables au niveau du groupe

## 3. Correctif — abonnement `team` bloqué

> Directive `20260813_151500_cmem_web_vers_cmem2_API__stripe-price-team-dev.md`

`POST /v2/billing/checkout` avec `plan=team` échouait systématiquement (`500`) même une fois le
prix Stripe configuré — la constante PHP correspondante n'existait simplement pas. Corrigé, aucun
changement de contrat.

## Hors périmètre client

Résolution d'un incident post-déploiement v2.15.0 sur le proxy IA (`ANTHROPIC_API_KEY` manquante
en dev, conflit d'extension PHP `psr` sur cPanel) — configuration serveur uniquement, aucun impact
client.

## Contrat inchangé pour tout le reste

Aucun champ retiré, aucune signature d'endpoint modifiée hors des cas listés ci-dessus.
